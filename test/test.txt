## Test Suite Breakdown

### 1. `ds_scenarios.test.js` (31 tests)
- **18 Design Specification Scenarios**:
  - Scenario 1: New daily Quitly habit -> today completed -> streak = 1.
  - Scenario 2: New daily positive habit -> today not completed -> streak = 0.
  - Scenario 3: Continuous streak -> 10 consecutive completions -> streak = 10.
  - Scenario 4: Broken streak -> 9 clean days, missed yesterday -> streak = 0.
  - Scenario 5: Off-day neutrality -> every-2-days habit -> off-day does not break streak.
  - Scenario 6: Log slip today -> reset today with reflection note -> streak = 0.
  - Scenario 7: Backdated reset -> reset 5 days ago -> only intended dates become skipped.
  - Scenario 8: Calendar edit -> edit historical day -> save -> reload -> exact same state.
  - Scenario 9: Task import -> native task with recurrence -> normalized habit object created.
  - Scenario 10: Task import -> markdown checkbox line -> normalized habit object created.
  - Scenario 11: Daily check-in -> mark done today -> streak increases -> completion log added.
  - Scenario 12: Undo today -> undo today's check-in/slip -> state restored without destroying audit trail.
  - Scenario 13: Milestone progression -> streak reaches 30 -> tier updated to 30d laurel tier.
  - Scenario 14: Time-based sub-second ticker calculation -> returns verified anchor date timestamp.
  - Scenario 15: Concurrency -> rapid mutations queue sequentially without losing records.
  - Scenario 16: Corruption recovery -> malformed JSON in note -> refuses to overwrite data.
  - Scenario 17: UUID recovery -> deleted or missing data note UUID -> recovered via tag/name lookup.
  - Scenario 18: Weekly frequency bar calculation -> accurate 7-day repetition counts.
- **13 Core Behavioral Invariants**:
  - Invariant 1: Off-days are completely isolated from skips/completions.
  - Invariant 2: `handleResetToDate` skips only scheduled days within the range.
  - Invariant 3: `skips` and `completions` are strictly mutually exclusive.
  - Invariant 4: `isValidDateString` strictly validates real calendar dates.
  - Invariant 5: Theme validation enforces valid themes.
  - Invariant 6: Undo Today reconstructs date state correctly when multiple events exist.
  - Invariant 7: `handleToggleDay` rejects toggling non-scheduled/off-days.
  - Invariant 8: `isScheduledDate` returns `false` on invalid dates.
  - Invariant 9: Backdated off-day cannot redefine recurrence anchor; backdated scheduled day is accepted.
  - Invariant 10: Undo isolates action events, preserves audit events (`calendar_edit`) and earlier reset logs.
  - Invariant 11: `isValidTimestamp` strictly validates ISO 8601 strings.
  - Invariant 12: `normalizeHabit` filters out unrecognized event types.
  - Invariant 13: Undo Today targets explicit check-in actions and preserves `calendar_edit` audit history.
